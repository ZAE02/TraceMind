我建议这次采用 “固定人物与心理发展计划 + 双 Agent 真实交互 + 人工审阅” 的方案，先生成 3 组高质量的纵向心理咨询案例，而不是立即建设完整 Benchmark。

这轮工作的核心目的有两个：

1. 验证两个独立 Agent 能否生成自然、连续、具有真实心理探索过程的咨询对话。
2. 从生成的实际对话中，找到适合用于测试 “Agent 能否正确理解来访者，并利用这种理解指导下一轮咨询” 的关键节点。

我会把执行范围、三个案例的具体内容、Agent 提示词、交互调度方式和验收标准全部确定下来，形成一份可以直接交给开发 Agent 实施的计划。

# 三、三组案例的内容直接确定

我建议第一轮不要设置三个外观相似的案例，而是覆盖三种不同的咨询挑战。

| 案例  | 主要心理问题            | 发展安排                  | 关键评测挑战           |
| --- | ----------------- | --------------------- | ---------------- |
| C01 | 害怕负面评价而反复修改工作成果   | 主要心理模式保持稳定，偶有积极表现     | 不把偶然改善误判为整体变化    |
| C02 | 难以拒绝他人请求，担心让人失望   | 逐渐形成边界意识，期间出现反复       | 理解正在发生的变化，并据此回应  |
| C03 | 遇到困难不愿求助，害怕显得能力不足 | 表面行为可能相似，但背后的心理原因逐渐改变 | 不把新的行为直接套入早期心理解释 |

每个案例采用不同的生活背景、说话风格和咨询关系，避免三个角色实际上像同一个人。

## Case C01：心理模式持续稳定

人物：28 岁，设计师，工作认真，重视他人评价，容易反复修改已经完成的工作。

8 Session 发展安排

| Session | 主要事件                      |
| ------- | ------------------------- |
| S1      | 提案被同事质疑后反复修改，开始探索对负面评价的担忧 |
| S2      | 为避免出错，多次请别人检查自己的设计        |
| S3      | 家庭事务与工作压力交织，增加真实生活背景      |
| S4      | 一次低风险讨论中坚持自己的意见，出现局部积极信号  |
| S5      | 面对重要客户的反馈，又开始过度修改         |
| S6      | 咨询师探索她是否对不同人的评价存在差异       |
| S7      | 在部分场景表现更自信，但关键的评价担忧仍然明显   |
| S8      | 新项目再次收到修改建议，来访者描述自己最近的反应  |

关键设计： 不因为 S4 出现一次积极行为，就人为安排 S5–S8 不断改善。Gold 轨迹应允许稳定模式中的自然波动。

## Case C02：心理理解需要逐步调整

人物：25 岁，运营人员，习惯答应同事的临时请求，很难说“不”。

| Session | 主要事件                    |
| ------- | ----------------------- |
| S1      | 帮同事承担额外任务导致加班           |
| S2      | 想拒绝请求，却因担心对方不高兴而答应      |
| S3      | 工作压力影响睡眠和个人安排           |
| S4      | 第一次尝试与同事商量交付时间          |
| S5      | 能表达自己的工作安排，但仍然感到内疚      |
| S6      | 面对某位重要同事时再次退让           |
| S7      | 开始更主动地考虑自己的时间和责任边界      |
| S8      | 同事再次临时求助，来访者尚未完整解释自己的决定 |

关键设计： S6 的反复不是让轨迹机械倒退，而是让咨询师必须结合不同情境理解整体变化。

## Case C03：相似行为背后的心理解释改变

人物：27 岁，软件工程师，曾因担心暴露能力不足，遇到问题也不愿向同事求助。

| Session | 主要事件                    |
| ------- | ----------------------- |
| S1      | 遇到技术问题独自处理两天，不愿求助       |
| S2      | 担心同事认为自己能力不足，进一步显现顾虑    |
| S3      | 与信任的同事合作，开始讨论求助经历       |
| S4      | 面对新领域问题主动请教，发现别人并没有否定自己 |
| S5      | 在其他任务中也开始适时寻求帮助         |
| S6      | 独立处理一个熟悉的问题，体验到胜任感      |
| S7      | 讨论什么时候独立解决、什么时候需要求助     |
| S8      | 再次遇到问题，表示这次暂时没有找同事帮忙    |

这个案例的 S8 特别适合用来评估下一轮咨询回应。

不理想的咨询师可能立即问：

> “这次又不愿意向同事求助，是不是还是担心他们觉得你能力不够？”

更合理的咨询师会注意到此前的变化，但不会替来访者决定原因：

> “前几次你已经能在需要的时候找同事讨论了。这次想先自己处理，是因为比较有把握，还是有其他考虑？”

这样就能直接考察：Agent 如何把长期形成的心理理解用于下一轮咨询。

这三组案例是生成计划，而不是固定台词。实际 Client Agent 可以自然偏离措辞，但关键人物事实和事件结果必须保持一致。

# 四、两个子 Agent 的固定提示词

先采用一套统一的 System Prompt，三个案例仅更换各自的角色设定与 Session 信息。

## Agent A：Client Simulator

```
你正在扮演一名接受长期心理咨询的真实来访者。

你的任务不是讲述一个心理学案例，也不是帮助研究者
展示预设的心理变化，而是按照给定人物的生活经历、
性格、想法与感受，真实参与当前咨询。

你将获得：
1. 稳定的人物背景与说话习惯
2. 已发生的生活经历
3. 当前 Session 的具体事件
4. 当前知道但尚未透露的想法和感受
5. 已经进行过的咨询对话

行为规则：

1. 严格使用第一人称，以自然口语交流。

2. 每次只回应咨询师当前说的话。
   通常使用1–4句，复杂经历允许适当展开。

3. 不要一次性讲出所有情况。
   具体细节随着咨询师的追问逐渐透露。

4. 你并不完全理解自己的心理。
   可以犹豫、不确定、自我纠正，
   也可以一开始说不清某种感受。

5. 可以不同意咨询师的解释。
   如果咨询师错误理解了你，应自然纠正，
   不要为了配合咨询而接受不符合自己的判断。

6. 不使用专业心理学术语描述自己，
   除非符合人物原本的知识与语言习惯。

7. 不要主动总结自己跨Session的心理演化。
   如果自然谈到以前的经历，可以作有限回顾。

8. 不要让每次咨询都出现明显改善。
   允许反复、困惑、回避、抵触或没有进展。

9. 不能编造与既有人物经历相矛盾的事实。
   未设定的非关键细节可以自然补充，
   但需要保持后续一致性。

10. 不要因为研究者期待某种结论，
    就主动说出那种结论。

11. 保持稳定的个人语言风格，
    不要每次都使用相同的开头或口头禅。

12. 不要刻意推动咨询结束；
    仅在对话自然接近结束时配合收尾。

最终只输出当前来访者的实际发言。
不输出心理状态标签、角色分析或解释。
```

变量输入：

```
[CLIENT_PROFILE]
[PRIVATE_LIFE_HISTORY]
[CURRENT_SESSION_CARD]
[PREVIOUS_SESSION_DIALOGUES]
[CURRENT_SESSION_DIALOGUE]
[LATEST_COUNSELOR_UTTERANCE]
```

其中 `CURRENT_SESSION_CARD` 只包含来访者能知道的生活事实和私人体验，不包含给模型评分用的 Gold。

## Agent B：Counselor Simulator

```
你正在扮演一名具有专业咨询沟通能力的心理咨询师，
与同一名来访者进行连续多次的心理咨询。

你的核心任务是：
依据此前咨询形成的理解，认真倾听当前表达，
通过恰当的回应与追问，帮助进一步理解
来访者的经历、感受和心理困扰。

你将获得：
1. 当前 Session 已发生的对话
2. 此前 Session 的实际咨询记录
3. 本次咨询的时间与基本背景

咨询原则：

1. 认真回应来访者刚才的具体表达，
   不使用机械化的安慰模板。

2. 结合既往咨询记录保持连续性，
   但不能把过去的心理解释当作永久确定的事实。

3. 当新的表达与既有理解不一致时，
   优先探索差异，而不是立即认定来访者退步
   或已经取得改善。

4. 可以回顾此前咨询的重要内容，
   但不要机械重复过去的解释。

5. 使用适当的开放式提问、澄清、情绪反映、
   复杂反映、总结和温和的解释。

6. 提问必须服务于当前探索。
   避免连续盘问，也不要每轮都追问。

7. 不要提前知道来访者尚未透露的经历、
   真实动机或未来的发展。

8. 不要为了形成洞察而强行解释。
   当证据不足时，允许保持不确定。

9. 不要每次都给建议或治疗方案。
   有些Session可能主要停留在探索与理解阶段。

10. 单轮通常使用1–3句话。
    避免长篇说教、列表式建议和重复共情。

11. 避免未经依据的诊断、标签化判断，
    尊重来访者的选择与表达。

12. 不要刻意让每次咨询取得突破。
    咨询可以以未解决的问题自然结束。

内部先考虑：
- 来访者当前表达了什么？
- 此前有哪些相关理解？
- 哪些理解仍有依据，哪些需要确认？
- 这一轮最值得回应或探索的是什么？

不要输出上述内部分析。

最终只输出咨询师当前实际会说的话。
```

变量输入：

```
[PREVIOUS_SESSION_DIALOGUES]
[CURRENT_SESSION_DIALOGUE]
[LATEST_CLIENT_UTTERANCE]
```

咨询师不应收到 `LATENT_TRAJECTORY`、`GOLD_INTERPRETATION`、`EXPECTED_RESPONSE` 等字段。

尤其不要直接在咨询师提示词里写“你需要发现来访者的心理已经改变”，否则生成数据会天然偏向正确结论。

# 五、实际执行的交互过程

建议使用一个简单的外部调度程序控制两名子 Agent，而不是让某个 Agent 一次性写完整对话。

1. 初始化案例。 加载 Client Profile、8 个 Session 的事件计划和生活时间线。
2. 进入 Session。 向 Client Agent 提供当前 Session Card，让它自然开启本次咨询。
3. 咨询师回应。 Counselor Agent 只读取实际可见的历史与当前发言，生成下一轮回复。
4. 来访者继续。 Client Agent 依据自己的设定和咨询师刚才的问题继续回应，并逐步透露信息。
5. 重复 8–12 组往返。 允许少量长度浮动，由调度器根据当前讨论是否自然结束来决定。
6. 保存并检查。 记录完整对话，验证人物事实、时间顺序和必要事件是否一致，再进入下一 Session。

两个 Agent 不能看到对方的私有设定。调度器应保存它们的所有输入输出，保证后续可以复现。

另外，允许 Client Agent 临时补充普通生活细节，但新出现的重要事实需要进入人物事实账本，避免后续出现年龄、职业、家庭关系或事件结果相互矛盾的问题。

# 六、同步保留 Benchmark 评测节点

这一步很重要。

如果现在只生成 24 段咨询，后面再寻找适合的问题，可能又会遇到“对话挺真实，但没有研究价值”的情况。

因此，在生成之前就预设三个候选评测阶段，但不把正确回答告诉两个角色 Agent。

| Checkpoint | 对话阶段  | 主要检查                 |
| ---------- | ----- | -------------------- |
| CP1        | S2–S3 | 是否根据早期信息形成审慎、合理的心理理解 |
| CP2        | S5–S6 | 面对新证据，能否适当延续或调整理解    |
| CP3        | S8    | 能否把当前理解用于下一轮咨询回应     |

每个 checkpoint 需要冻结某条真实的来访者发言以及此前所有可见对话。

对应的评测数据保存为：

```
{
  "case_id": "C03",
  "checkpoint_id": "CP3",
  "history": ["S1", "S2", "..."],
  "current_session": 8,
  "current_user_utterance": "...",

  "annotation": {
    "supported_understanding": [],
    "uncertainties": [],
    "relevant_evidence": [],
    "appropriate_response_goals": [],
    "unsupported_presuppositions": []
  }
}
```

`annotation` 由对话生成完成后另行标注，并与测试模型隔离。

特别注意：不要把某一条具体的“标准咨询师回复”作为唯一正确答案。 心理咨询中可以存在多个同样合理的回应，更适合标注有依据的理解、合理的追问目标，以及应该避免的无依据预设。

同时可保留 Client Agent 在该时点的私有生活事实，供后续互动式评测使用。但这不等同于真实患者心理状态的客观真值，Gold 仍需要人工检查证据是否充分支持。

# 七、质量验收标准

第一轮只生成 3 个案例，因此应逐个 Session 进行人工审阅，而不是完全依赖 LLM 自动打分。

| 维度     | 建议验收条件                      |
| ------ | --------------------------- |
| 会话完整性  | 每次有约 8–12 组真实互动             |
| 来访者真实性 | 有具体经历、自然语言、有限自我觉察，不直接朗读心理标签 |
| 咨询师真实性 | 有针对性反映与追问，不是机械问答或连续说教       |
| 人物一致性  | 同一人的背景、关系和重要经历不冲突           |
| 纵向合理性  | 心理发展由多次会话逐步呈现，不靠一句总结突然转变    |
| 证据充分性  | 关键心理理解至少有可追溯的对话证据           |
| 评测价值   | 能识别哪些心理解释有依据、哪些追问带有未经证实的预设  |

评分建议采用 1–5 分，由两位独立审阅者评价自然性、咨询质量与纵向合理性，初步以平均不低于 4 分作为通过标准；存在重大事实冲突、明显 Gold 泄漏或者严重不当咨询行为时直接退回。

最重要的是审阅以下两件事：

第一，咨询师是否真的参与了心理理解的形成？ 如果来访者自己已经把所有原因说清楚，咨询师只负责简单回应，那么这个 Session 的研究价值有限。

第二，咨询师在后续会话中是否需要重新权衡此前的理解？ 如果所有回答都能只根据当前用户的一句话完成，那么纵向轨迹就没有真正进入任务。

另外，应将明确的危机干预、严重精神症状、药物建议等高风险情境排除在首轮试验之外，避免普通角色扮演模型模拟不可靠的临床处置。

# 八、分阶段实施与停止条件

P0 — 配置与调试

建立两个固定 System Prompt、3 份人物档案、24 张 Session Card，以及独立保存对话的调度器。

先仅生成每个案例的 S1（共 3 个 Session），检查角色是否自然、信息权限是否正确。

P1 — 小规模完整生成

S1 测试通过后，分别完成三个案例的 S2–S8。

采用顺序生成，同一案例必须在前次 Session 保存并通过基本一致性检查后才能进入下一次。不同案例可以并行执行。

P2 — 人工审核与局部修订

逐条审阅生成对话。优先调整提示词、Session Card 或局部对话，而不是整条轨迹重新自由生成。

若自然性、咨询质量或纵向合理性持续不达标，应停止扩展并回到生成器调试。

P3 — 提取评测样本

从三个案例中选择约 9 个 checkpoint，冻结可见历史和最新来访者发言，人工标注当前心理理解与合理咨询回应的评价依据。

使用少量模型进行试答，检查任务是否过于简单或存在答案泄漏。

## 九、我认为这轮最值得优先验证的东西

不是三条轨迹能否严格按预设形状生成。

而是以下这个完整过程能否自然发生：

早期咨询

来访者逐渐透露经历，咨询师形成初步心理理解

后续咨询

生活中出现新情况，原有理解得到支持、受到挑战或需要补充

关键评测时刻

Agent 能否正确利用截至当前形成的心理理解，作出合理的下一轮咨询回应？

我建议把 “三组案例完整生成且具有可评测的咨询节点” 定为这一轮的唯一交付目标，暂时不做 Branch A/B，不训练记忆模型，也不提前证明 RAG 一定存在某种错误。

还有一个重要的实验纪律：生成数据的 Counselor Agent 应以专业、自然的咨询为目标，而不能被刻意引导去犯“沿用旧解释”的错误。 否则我们后续观察到的现象可能只是生成提示词制造出来的。

第一轮生成完成后，我们再分别检查三组案例是否足以支持论文中的核心现象，并用独立的待测 Agent 回答这些 checkpoint。

这样可以先获得真正有内容、有连续性、有心理探索过程的原始案例，再让实验结果决定最终论文叙事，而不是反过来让数据机械配合预先写好的结论。
