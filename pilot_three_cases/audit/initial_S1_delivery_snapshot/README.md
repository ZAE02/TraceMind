# 三组纵向咨询案例试生成

所有案例均为拟真合成材料，非真实患者记录。本轮范围是 C01、C02、C03 的 S1；S2–S8 等待人工审阅。

三个S1已完成，分别有12、10、12组往返，共68条角色发言。21项测试及实际请求权限和可追溯性检查通过。请从 [S1审阅入口](audit/review_packet.md) 阅读对话和填写人工评分；模型预审已列出需要核对的问题，尚未认定案例通过人工质量验收。

原业务空间地址对 Qwen 和 DeepSeek 均返回 HTTP 403 `Endpoint.AccessDenied`。同一密钥在官方北京通用入口完成了最小连通性测试（HTTP 200，Qwen回复OK），当前已将生成地址改为 `https://dashscope.aliyuncs.com/compatible-mode/v1` 并继续使用 Qwen。原地址、模型切换和诊断记录均保留在 `audit/` 和配置修订目录；诊断回复不会计入咨询案例。模拟测试数据只存在于临时测试目录。

## 使用

运行环境：Python 3.9 或以上；生成器只使用标准库，无需安装 SDK。生成前会自动检查24张卡的48份角色输入构造，也可以单独运行预检查。

首次初始化（已经完成后不要重复运行）：

```powershell
python .\prepare.py --source-plan '原始计划文本的绝对路径'
```

在当前终端会话设置 `DASHSCOPE_API_KEY`。密钥只从生成进程环境读取，请勿写入项目文件。然后运行：

```powershell
python .\generator.py --phase preflight
python .\generator.py --phase s1
python .\generator.py --phase check
python -m unittest discover -s tests -v
```

同一命令可恢复中断的运行：已保存的发言不会重发，已完成的会话不会重新生成。模型请求成功但对话文件尚未提交时，可以从调用日志恢复。HTTP 超时后服务端是否已处理无法确定，重试可能产生额外计费，日志会保留全部尝试。

生成器使用进程锁防止重复启动。进程被强制终止后，先确认锁中PID已退出，再移除 `generation_logs/runner.lock`；正常结束或已处理的异常会自动清理锁。

模型或格式不支持、鉴权失败、响应截断和空回复会停止生成。若要改动已有实验配置或修订对话，请保留原始输出，另建版本并记录原因；生成器拒绝在上下文或配置变化后静默接续。

## 信息权限与调度

配置使用指定的 Qwen 模型和 Responses 接口。来访者与咨询师具有各自的 system prompt；每次只请求一个角色的一条发言。两个角色使用同一模型，不共享服务端会话。

来访者能看人物档案、此前已发生的生活事件、当前会话私人体验和实际对话；看不到未来会话卡、研究标签或标注。咨询师只看实际既往对话、当前对话及中性的会话时间信息。研究计划独立保存，永不参与角色请求。

每次以10组往返为目标，8组以后若双方明确收尾可结束，9组开始提示时间接近结束，12组为硬上限。心理进展不作为结束条件。

## 文件与审阅

- `configs/`：两份原始固定提示词、生成参数、三份人物与24张会话卡；`research_plans/` 仅供研究者使用。
- `dialogues/`：逐条保存的 JSON 原始发言与 Markdown 阅读版；每条有唯一编号和调用引用。
- `generation_logs/`：不含认证头的完整请求与响应、参数、时间、重试、模型返回标识；用于审计，不向待测模型开放。
- `facts/`：稳定事实、经核验的新事实及待检查会话；新事实必须附发言编号、核验理由和首次出现会话。
- `audit/`：程序检查、模型预审、事实一致性记录、两人独立人工评分和三份阅读表。
- `checkpoints/`：本轮为空，标明推迟到完整案例生成后提取，不能当作已完成的评测样本。

`audit/quality_scores.json` 的人工评分默认为 `null`。两位不同的人工审阅者分别对自然性、咨询质量、纵向合理性打1–5分；S1的纵向合理性仅评起点可信度和可延展性。六项平均≥4，且两人均明确确认 `major_issues=[]`，才能通过人工门槛。人工身份、时间与反馈应真实填写。

模型预审独立记录，不能冒充人工评分。程序通过只证明结构、请求权限和记录完整性，不证明临床有效性或整条心理发展合理。

## S1审阅后的续作

本轮停在三份S1的人工审阅。收到反馈后先完成必要修订和事实核验，保存原始版本及修改原因。三个S1均通过人工门槛、各自连续性检查通过后，可按次运行：

```powershell
python .\generator.py --phase session --case C01 --session 2
```

每次后续会话需先完成上一会话的事实/连续性核验，再进入下一次。核验将 `continuity_review.status` 标为 `passed`，注明核验者、证据与问题；补充事实先与人物档案和已有事实比对，确认后加入 `confirmed_additions`，保留修订记录。人工反馈不得由程序代填。

完成S2–S8后，从S2–S3、S5–S6、S8各选一个真实发言时点，冻结此前历史和当前来访者发言。可见输入、研究标注和互动评测用私人事实分开导出；不把当前咨询师后续回复或未来会话送入待测模型。

接口依据：[阿里云 Responses API 文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)。
