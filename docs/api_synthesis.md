# Gemini 单批数据合成

数据合成从 Terra 子 Agent 切换到 `gemini-3.8-flash`，不覆盖或重新标注旧 Terra 结果。20 组已有场景计划作为有来源的种子保留，新的发言使用 `gemini_v1` namespace；不能将旧发言计为 Gemini 产物。评测模型及已冻结的旧评测协议不在本次切换中悄然修改。

每次实际 HTTP 请求前读取[项目 skill](../.agents/skills/tracemind-api/SKILL.md)。用户在首批完成后已明确取消每日请求上限与每批 20 条限制，并将全局开始间隔改为至少 10 秒、并发上限改为 4。跨进程槽位锁限制在途请求，SQLite 原子事务保证所有线程/进程共享开始间隔；同一任务禁止并发重试，同一轨迹仍逐条生成；全部尝试、模型列表查询、失败及重试继续按本地账本保存。429 的等待、同任务最多三次总尝试均跨进程保留；401/403、账户/服务提示及未批准的模型标识差异仍会阻止后续调用，必须处理根因，不自动清除。

当前执行器不指定 `--limit` 时持续合成现有 20 组获批场景；可显式指定较小的 `--limit` 用于有限运行。一次发言对应一次生成请求；共享开场单独生成、跨反事实轨迹复用，不重复计为四次生成。全部场景合成结束才退出；错误或本地 STOP 标记会提前停止。重启同一运行会从已落盘结果恢复，不因本地导入中断重复请求。2026-10-30 首个 20 条批次仍保留其当时限制和结果的历史报告。

已完成会话在后续发言生成前进入独立的模型内容审查。审查请求包含当前会话、当前事件卡、稳定背景及少量既往公开锚点，不包含未来卡片。结果绑定会话哈希及真实任务来源；拒绝会保留问题并停止，不覆盖原对话或强制放行。格式错误也保存原始回复，恢复时不会为了修复格式重复请求。审查与生成使用同一模型的不同无状态请求，仍有同模型偏好，不能替代人工或临床认可。

审查通过后，完成会话使用真实 BGE-M3 及 PostgreSQL/pgvector 增量入库，已有一致记录不重新编码。审查请求也经过同一个单并发与时间间隔限制器，保存于独立 review 目录；不计为新增合成发言，API 请求统计则包含这些辅助任务。

输入仅包含当前角色允许的信息。咨询师没有私有设定；来访者只见最近两张已发生事件卡。过去会话采用至多五场的首末来访者发言，当前会话保留开场及最近八条发言，按 ID 去重；实际上下文不超过 12,000 字符，超出则停止检查，不切断某条发言。此选择策略记录为 `bounded-source-anchors-v1`，不等价于完整历史。

本地私有文件位于 `.local/api/`（尝试账本、响应、单批状态、实际输入与结果）和 `.local/datasets/gemini_v1/`（场景及生成材料）。密钥只在环境或 `.local/api-config.json`，不会写入请求正文、账本或提交文件。代理环境变量被禁用，HTTP 重定向被拒绝，避免隐式切换路由。

首批 `initial-gemini-20261030`：模型列表确认指定模型存在；第一条生成返回的 `model` 标识不一致，未接纳为数据。实际发出两次请求，接纳零条，停止后未重试。未保存该次原始响应的模型标识，因此不能进一步断言其实际底层模型；需要检查本地网关的模型映射。后续版本会在无密钥反射时保存响应以供诊断，不为补日志重新调用服务。

随后复用了本地代理记录，通过原请求输入哈希匹配到明确路由 `gemini-3.8-flash → gemini-3.8-flash-tiered`。用户授权的一条 128-token 最小中文对话返回 HTTP 200、有效正文和 `model=gemini-3.8-flash-tiered`，进一步确认了这一映射。用户已明确允许此返回名称。生产执行器保持请求名不变，将请求名、返回名及映射依据写入来源；仅接受这一精确映射，其他别名继续拦截。原始失败批次仍保留，不被事后改写成成功数据。
