# TraceMind architecture and operation

Evidence is stored in PostgreSQL with pgvector. Retrieval filters by case, turn and time before lexical and dense ranking. Memory stores immutable full revision snapshots; each statement links to supporting and refuting evidence. Corrections append statements referencing earlier statements. PostgreSQL stores a canonical SHA-256 chain and locks writes per subject.

Active synthesis uses `scripts/run_project.py` and the project API skill: four durable transport slot locks, an atomic shared request-start ledger and finite retry policy. The user removed daily and 20-record limits; starts remain at least 10 seconds apart globally with at most four in-flight requests. Omitting `--limit` continues until the approved scene trajectories are generated, a STOP marker is seen, or an error requires intervention. Each model call uses a bounded stateless role input; actual messages and requested/returned model identities are retained. Only the exact user-approved proxy alias is accepted. `scripts/start_synthesis.ps1` manages a hidden Windows background process without duplicating an existing runner. `scripts/audit_api_batch.py BATCH_ID` checks saved artifacts, model names, context boundaries and request timing without making API calls. Dataset generation completion does not imply content review or experiment completion.

The disabled Terra v2 generator used `scripts/dispatch_scoped.py`, one agent per trajectory-role and a fresh task per shared anchor. Existing v2 results remain a separate collection. Experimental and judge Agent jobs retain fresh per-job scopes; the synthesis provider change does not silently rewrite the legacy evaluation protocol. The old shared-worker dispatcher remains an engineering artifact.

The LangGraph workflow runs extract → retrieve → conflict → revise → validate → persist → respond. Active workflow starts use the designated Gemini API; model and reasoning are stored in the checkpoint and cannot switch during recovery. `tracemind workflow run-api` executes the persisted interrupts through the same API limiter and durable task queue as synthesis. Each transition reopens the actual PostgreSQL checkpointer, and completed task outputs are reused. Conflict/revision inputs pack historical evidence and prior memory under a shared 4,096-token limit; the response also uses a measured history envelope. The legacy external-Agent adapter and old checkpoint defaults remain available for archived jobs, but do not start new Terra synthesis. Result import checks the original request's model and reasoning, Agent/API execution identity, and JSON schema. These fields are reported provenance, not cryptographic proof of execution.

The full project additionally runs the production graph on the first public development checkpoint, recording its four actual model tasks, memory write and completed response in ignored `project/langgraph_run/`. This is a separate infrastructure demonstration. The six-method benchmark uses `ExperimentRunner` for controlled checkpoint-bound memory and retrieval inputs; it does not treat LangGraph orchestration itself as an experimentally isolated improvement.

Use `tracemind db init` after setting `TRACEMIND_DSN`, then `tracemind doctor` to inspect separate database, pgvector and model-cache readiness. Run `tracemind workflow run-api SUBJECT INPUT.json ALLOWED_IDS.json --thread-id STABLE_ID` to execute or recover the current API workflow. Input is a JSON object; allowed IDs are a JSON array of existing evidence identifiers. This command refuses concurrent execution while the full project holds its batch lock. `tracemind workflow start` queues an initial Gemini interrupt without executing it; `tracemind workflow resume` imports already completed queue results. Historical Agent results may still be imported using their original model/reasoning and actual provenance, but new current workflow jobs require API provenance. `tracemind memory history SUBJECT` displays saved revisions. Revise results contain additions only; prior records remain in the full append-only snapshot. A revise result contains `evidence` and `statements` arrays.

`tracemind review init DATABASE PACKETS REVIEWER_A REVIEWER_B` prompts for passwords; `tracemind review serve DATABASE` starts the review UI. Set a random `TRACEMIND_REVIEW_SECRET` of at least 32 characters before serving. PostgreSQL integration tests require `TRACEMIND_TEST_POSTGRES_DSN`; they are skipped without it. Checkpoint and memory stores are separate transactions, so replay is idempotent after a completed memory write. A checkpoint can recover its pending queue request if registration was interrupted.

Initialize benchmark plans with `tracemind benchmark init ROOT PLANS.json`, then repeatedly export/import the actual jobs and run `tracemind benchmark advance ROOT`. Once historical evidence is indexed, `tracemind benchmark advance ROOT --experiments` also advances the six methods. `tracemind benchmark audit ROOT --experiments` reports materialized candidates and queue counts. Oracle IDs require a separate public-evidence annotation and independent model review; this is model-reviewed evidence, not human gold. The runner measures serialized history and metadata under the 4096-token budget, and reports current conversation and instructions separately.

After dialogue generation, run `tracemind benchmark index ROOT` to embed completed sessions using the pinned BGE-M3 model. Existing records are compared and never re-embedded. Session dates are deterministic synthetic relative times, not real event timestamps. Workflow input must include `retrieval` with `query`, `cutoff` as `[session, turn]`, and timezone-aware `as_of`; only allowed evidence IDs are passed onward. Evolution uses append-only validated structured revisions, while on-demand builds a separate structured revision from the available history at each checkpoint. Summary remains a text summary.
