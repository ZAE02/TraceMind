# TraceMind architecture and operation

Evidence is stored in PostgreSQL with pgvector. Retrieval filters by case, turn and time before lexical and dense ranking. Memory stores immutable full revision snapshots; each statement links to supporting and refuting evidence. Corrections append statements referencing earlier statements. PostgreSQL stores a canonical SHA-256 chain and locks writes per subject.

Formal generation uses `scripts/dispatch_scoped.py`: one agent per trajectory and role, and one fresh task per shared anchor. Registry-controlled mailboxes prevent future anchors and other cases entering a role's context. The queue binds an actor identity to exactly one information scope and role. Experimental and judge jobs default to a fresh per-job scope, so generation agents cannot be reused for restricted experimental conditions. The old shared-worker dispatcher is an engineering artifact and must not produce formal data.

The LangGraph workflow runs extract → retrieve → conflict → revise → validate → persist → respond. Extraction, conflict review, revision and response are external agent jobs. The graph interrupts and records its state in PostgreSQL; the CLI queues the interrupt. A designated Codex agent must execute each exported job and save its actual result and provenance; Python does not call a model API. Result import checks the configured model and reasoning, agent task identity, and the job's JSON schema. These fields are reported provenance, not cryptographic proof of agent execution.

Use `tracemind db init` after setting `TRACEMIND_DSN`, then `tracemind doctor` to inspect separate database, pgvector and model-cache readiness. Start a run with `tracemind workflow start SUBJECT INPUT.json ALLOWED_IDS.json`. Input is a JSON object; allowed IDs are a JSON array of evidence identifiers. Run `tracemind jobs export DIRECTORY`, dispatch jobs to the designated agent, and import a JSON object `{ "job_id": "...", "result": {...}, "provenance": {"model": "gpt-6.1-terra", "reasoning": "medium", "agent_task": "..."} }` with `tracemind jobs import FILE`. Then `tracemind workflow resume THREAD_ID` advances until the next interrupt. Repeat until completed. `tracemind memory history SUBJECT` displays saved revisions. Revise results contain additions only; prior records are retained locally in the full append-only snapshot. A revise result contains `evidence` and `statements` arrays.

`tracemind review init DATABASE PACKETS REVIEWER_A REVIEWER_B` prompts for passwords; `tracemind review serve DATABASE` starts the review UI. Set a random `TRACEMIND_REVIEW_SECRET` of at least 32 characters before serving. PostgreSQL integration tests require `TRACEMIND_TEST_POSTGRES_DSN`; they are skipped without it. Checkpoint and memory stores are separate transactions, so replay is idempotent after a completed memory write. A checkpoint can recover its pending queue request if registration was interrupted.

Initialize benchmark plans with `tracemind benchmark init ROOT PLANS.json`, then repeatedly export/import the actual jobs and run `tracemind benchmark advance ROOT`. Once historical evidence is indexed, `tracemind benchmark advance ROOT --experiments` also advances the six methods. `tracemind benchmark audit ROOT --experiments` reports materialized candidates and queue counts. Oracle IDs require a separate public-evidence annotation and independent model review; this is model-reviewed evidence, not human gold. The runner measures serialized history and metadata under the 4096-token budget, and reports current conversation and instructions separately.

After dialogue generation, run `tracemind benchmark index ROOT` to embed completed sessions using the pinned BGE-M3 model. Existing records are compared and never re-embedded. Session dates are deterministic synthetic relative times, not real event timestamps. Workflow input must include `retrieval` with `query`, `cutoff` as `[session, turn]`, and timezone-aware `as_of`; only allowed evidence IDs are passed onward. Evolution uses append-only validated structured revisions, while on-demand builds a separate structured revision from the available history at each checkpoint. Summary remains a text summary.
