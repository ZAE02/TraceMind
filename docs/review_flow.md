# Session review and bounded adjudication

A rejected session is retained byte-for-byte with its original model judgment and source job. Session content rejection does not stop unrelated trajectories. The affected trajectory is quarantined so subsequent generation cannot depend on an unresolved source; unreviewed/quarantined sessions and their descendants are excluded from Gemini retrieval indexing and formal release.

`session-adjudication-v1-two-independent` permits exactly two additional isolated model review tasks per rejected source hash. They see the original bounded session review context, but neither the prior rejection nor each other's result. Each rejection must cite an existing utterance ID and an exact substring of that utterance. Approvals must have no findings. Only two valid approvals permit effective acceptance; any disagreement, rejection or unsupported quotation keeps the source quarantined. The decision and both immutable source jobs are saved separately under ignored `review_resolutions/`. Neither the original judgment nor test dialogue is overwritten. Restarting reuses the same decisions and jobs; there is no loop until approval.

This policy was introduced before formal calibration/protocol freezing after a source-unsubstantiated session rejection. It applies to future session rejections uniformly, including test data, and does not alter the formal answer-scoring protocol. Same-model/proxy correlation and selection of rejected sessions for adjudication are research limitations, not independent human validation. All actual judgments, disagreements, invalid evidence and adjudication calls must remain auditable and be reported.

The full 20/80/480/240 scope remains required. If all runnable trajectories finish while quarantined cases remain, status is `awaiting_quality_resolution`, with an explicit shortfall; it cannot be labeled a complete delivery or published as full-scope success. Transport, account/authentication, response-schema and storage failures retain their existing stop rules. Other experiment-specific approval gates are not silently bypassed by this session policy.

Local source-recovery failures are recorded separately in ignored `source_quarantines/`, never relabeled as model quality rejections. A missing original wire envelope must not be fabricated from a proxy log; preserve the proxy content and exact request match, exclude the affected trajectory pending auditable recovery, and do not repeat its successful HTTP call. Genuine account/service blocks remain global stops. A detector false positive can be repaired only with original local source evidence, offline regression tests and an audit of the specific control-state correction. HTTP200 JSON responses are now preserved before notice classification after the credential-reflection check, including responses that trigger a genuine notice stop.

HTTP200 JSON is written once per attempt. Atomic file replacement has six bounded local attempts for transient Windows PermissionError; these retries never call the model or reset API retry budgets. If an existing original response needs recovery after a local bookkeeping failure, verify its exact input hash, original body, model label and matching proxy record before completing the old ledger entry; preserve the original failure and leave unknown client timing missing.

For the two isolated session adjudication panels only, a saved response with invalid JSON or schema consumes that panel and counts as invalid evidence. Its raw response hash is retained; the result stays null and the trajectory remains quarantined. No syntax repair, replacement panel, or favorable retry is allowed. This narrow handling prevents a malformed adjudication from stopping unrelated trajectories. Authentication, transport, changed-input, storage failures and other task output errors still stop globally.

Eligible calibration can advance independently with `scripts/run_project.py --batch-id <existing-run> --ready-calibration`. It reuses the original fixed branch/stage schedule and existing model-list confirmation. A complete reviewed source prefix and the four counterfactual histories at the same stage are required. Existing results are reused by task hash. Missing unrelated sessions no longer block these tasks. The output inventory records eligible tasks and actual completed references. Full protocol freeze and full-scope release retain their original coverage requirements.
### Completion cohort

The pre-freeze completion run stages one replacement per unresolved trajectory. It retains accepted prefixes and shared openings, archives the original tail and its review records by content hash, and only stages tails with no indexed evidence or affected evaluation answers. Each replacement has its own generation inputs and receives the normal session review. Existing accepted reviews and completed jobs are reused. The final report identifies the replacement cohort and its scope. This version does not reduce the full delivery counts or turn an earlier rejection into an approval.

In blinded quality output, a redundant Boolean `has_error` can be retained as unscored metadata if it exactly matches the OR of the three required error flags. Scores, detailed error flags and preference still have to validate against the original schema.
