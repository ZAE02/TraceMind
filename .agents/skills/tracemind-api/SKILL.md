# TraceMind API 调用限制

每次实际 HTTP 请求（含模型列表和重试）之前重新读取本文件。使用 `tracemind.api_client` 执行请求，禁止绕开持久化限流器。此规则适用于本项目的所有生成模型 API 调用；不影响本地模型权重推理或 Git 操作。

## 连接与凭证

- 地址和密钥从环境变量或忽略提交的本地配置读取；密钥不得进入代码、数据集、日志或输出文件。
- 仅使用用户指定的 `gemini-3.8-flash`。每批开始先读取可用模型列表，确认精确模型名存在；不存在就停止。
- 用户已明确允许代理映射：请求仍为 `gemini-3.8-flash`，响应可为 `gemini-3.8-flash-tiered`。同时记录请求名、返回名及映射依据；不得据此接受其他别名或改发返回名称。
- 不自动切换账号、轮换代理或绕过服务端限制。不预热、压测或无意义轮询。

## 请求控制

- 全局并发最多 4；任意两次请求开始时间至少相隔 10 秒（全局共享，非每个工作线程各计）。同一轨迹仍逐条依赖生成，不并发生成互相依赖的发言。
- 用户已取消每日请求数量上限；继续按 Asia/Shanghai 日期记录全部尝试、失败及重试，保留可审计计数。
- 用户已取消每批 20 条限制，可持续推进已授权的 20 组场景目标，直至完成、用户停止或触发错误停止条件。不得自行扩展到额外场景。一次发言为一条合成记录；共享开场单独计一条，不重复计入四条轨迹。
- 每条发言独立生成、角色交替；仅发送当前样本必要的上下文。不得反复发送整个数据集或不断增长的完整历史。受控压缩时记录所选证据 ID 及上下文策略，不能声称与完整历史条件等价。

## 错误处理

- 429：立即暂停；遵守 Retry-After（秒数或 HTTP 日期），缺失/无法解释时至少等待 300 秒。同一任务最多重试 2 次，再次失败停止并报告。等待跨进程持久化。
- 403、账户验证、服务禁用、违反条款提示：停止整个任务，不重试、不换账号，保存脱敏错误。
- 401：停止任务并检查配置，不连续尝试。
- 超时或 5xx：指数退避，最多重试 2 次，连续失败停止；重试仍须满足开始时间间隔。
- 其他请求/响应格式错误停止报告，不用无上限重试修补。
- 严禁无限重试、并发重试、失败后立即重复发送。中断后通过任务哈希及本地尝试账本恢复，不重置同任务重试计数。
